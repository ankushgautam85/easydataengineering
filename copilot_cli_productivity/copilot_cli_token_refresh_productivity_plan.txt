COPILOT CLI TOKEN REFRESH AND SOFTWARE ENGINEERING PRODUCTIVITY IMPLEMENTATION PLAN
==================================================================================

PURPOSE
-------

Enable software engineers to use company-hosted open-source LLMs that are available only through Copilot CLI, while preserving the team's existing Visual Studio Code workflow and reusing the current Git repository configuration under:

.github/
  copilot-instructions.md
  instructions/
  agents/
  skills/

The design intentionally minimizes setup and developer behavior changes.

Primary goals:

1. Keep Visual Studio Code as the main engineering environment.
2. Use Copilot Chat for small, convenient interactions.
3. Use Copilot CLI for high-token, agentic, repository-level software development.
4. Reuse all existing .github instructions, skills, and agents.
5. Hide manual credential/environment-variable setup.
6. Reduce hourly Azure SSO token refresh to one command plus the mandatory SSO interaction.
7. Preserve Copilot CLI task context across token refreshes.
8. Use company-hosted open-source models as the default engine for token-heavy work.
9. Avoid introducing a new RAG system, context store, VS Code extension, or duplicated AI configuration.
10. Keep short-lived credentials process-scoped rather than persist them on disk.

TOKEN REFRESH PROBLEM
---------------------

Current process:

1. Run a token-refresh script.
2. Script generates a device code.
3. Developer opens Azure SSO portal.
4. Developer enters the device code.
5. Authentication completes.
6. Key/token is returned to the terminal.
7. Developer manually adds the value as an environment variable in PowerShell.
8. Copilot CLI is launched.
9. Approximately one hour later the process repeats.

This is too much friction for broad CLI adoption.

The optimized workflow should be:

    ai / aic
       |
       +-- Check credential state
       |
       +-- Credential valid?
               |
          +----+----+
          |         |
         YES       NO
          |         |
          |         +-- Run existing company auth script
          |                  |
          |                  +-- Device code generated
          |                  +-- Azure SSO
          |                  +-- New credential returned
          |                  +-- Set process environment variable
          |
          +---------+
                    |
                    +-- Set OSS model environment variable
                    |
                    +-- Launch Copilot CLI
                            |
                            +-- New session for ai
                            |
                            +-- Continue previous session for aic


SECURITY PRINCIPLES
-------------------

Do not persist the one-hour token using:

    setx

or:

    [Environment]::SetEnvironmentVariable(..., "User")

or:

    [Environment]::SetEnvironmentVariable(..., "Machine")

The credential should remain process-scoped.

Use:

    $env:COMPANY_COPILOT_TOKEN = $token

or:

    [Environment]::SetEnvironmentVariable(
        "COMPANY_COPILOT_TOKEN",
        $token,
        [EnvironmentVariableTarget]::Process
    )

The resulting process hierarchy should be:

    PowerShell
        |
        +-- Temporary credential
        |
        +-- Copilot CLI
                |
                +-- Inherits temporary credential

Only non-secret metadata should be persisted locally.

For example:

    issuedAt
    expiresAt
    model

Never persist:

    access token
    secret
    generated API key
    refresh credential


CHANGE TO EXISTING AUTHENTICATION SCRIPT
----------------------------------------

The existing company refresh script should continue handling Azure SSO exactly as it does today.

The only recommended change is that after successful authentication it should place the generated credential into an environment variable in the current PowerShell process.

Example:

    $env:COMPANY_COPILOT_REFRESHED_KEY = $generatedKey

If the authentication script knows the actual expiration time, also expose:

    $env:COMPANY_COPILOT_KEY_EXPIRES_AT = $expirationTime.ToString("o")

If the script does not know the expiration time, the launcher can assume the current one-hour lifetime.

If possible, also improve the SSO UX by:

1. Copying the generated device code to the clipboard.
2. Opening the approved Azure device-login page automatically.
3. Displaying a clear message in the terminal.
4. Waiting for the existing authentication process to complete.

Example concept:

    Set-Clipboard $deviceCode
    Start-Process $AzureDeviceLoginUrl

This must not bypass SSO, MFA, company authentication policies, or the existing token-generation mechanism.


REFERENCE POWERSHELL LAUNCHER
-----------------------------

Save as:

    C:\company\copilot\ai.ps1

Replace configuration placeholders with the actual company values.


    param(
        [switch]$Continue,
        [switch]$ForceRefresh
    )

    Set-StrictMode -Version Latest
    $ErrorActionPreference = "Stop"

    # ============================================================
    # CONFIGURATION
    # ============================================================

    # Existing company token-refresh script.
    $CompanyRefreshScript = "C:\company\copilot\refresh-token.ps1"

    # Environment variable populated by the refresh script.
    $RefreshOutputEnvVar = "COMPANY_COPILOT_REFRESHED_KEY"

    # Environment variable expected by the Copilot/Bedrock integration.
    $CopilotCredentialEnvVar = "YOUR_COPILOT_CREDENTIAL_ENV_VAR"

    # Environment variable used to choose the company OSS model.
    $CopilotModelEnvVar = "YOUR_COPILOT_MODEL_ENV_VAR"

    # Company-approved OSS model.
    $CopilotModel = "YOUR_COMPANY_OSS_MODEL"

    # Current credentials last approximately 60 minutes.
    $CredentialLifetimeMinutes = 60

    # Refresh before the credential actually expires.
    $RefreshBufferMinutes = 8

    # Metadata only. NO TOKEN is written here.
    $StateDirectory = Join-Path $HOME ".company-copilot"
    $StateFile = Join-Path $StateDirectory "auth-state.json"


    # ============================================================
    # HELPER FUNCTIONS
    # ============================================================

    function Get-ProcessEnvironmentVariable {
        param(
            [Parameter(Mandatory)]
            [string]$Name
        )

        return [Environment]::GetEnvironmentVariable(
            $Name,
            [EnvironmentVariableTarget]::Process
        )
    }


    function Set-ProcessEnvironmentVariable {
        param(
            [Parameter(Mandatory)]
            [string]$Name,

            [Parameter(Mandatory)]
            [string]$Value
        )

        [Environment]::SetEnvironmentVariable(
            $Name,
            $Value,
            [EnvironmentVariableTarget]::Process
        )
    }


    function Get-AuthState {

        if (-not (Test-Path $StateFile)) {
            return $null
        }

        try {
            return Get-Content $StateFile -Raw | ConvertFrom-Json
        }
        catch {
            return $null
        }
    }


    function Save-AuthState {

        param(
            [Parameter(Mandatory)]
            [DateTime]$IssuedAt,

            [Parameter(Mandatory)]
            [DateTime]$ExpiresAt
        )

        if (-not (Test-Path $StateDirectory)) {
            New-Item `
                -ItemType Directory `
                -Path $StateDirectory `
                -Force | Out-Null
        }

        $state = @{
            issuedAt  = $IssuedAt.ToString("o")
            expiresAt = $ExpiresAt.ToString("o")
            model     = $CopilotModel
        }

        $state |
            ConvertTo-Json |
            Set-Content `
                -Path $StateFile `
                -Encoding UTF8
    }


    function Test-CredentialRefreshRequired {

        if ($ForceRefresh) {
            return $true
        }

        $credential =
            Get-ProcessEnvironmentVariable `
                -Name $CopilotCredentialEnvVar

        if ([string]::IsNullOrWhiteSpace($credential)) {
            return $true
        }

        $state = Get-AuthState

        if ($null -eq $state) {
            return $true
        }

        try {
            $expiresAt =
                [DateTime]::Parse($state.expiresAt)

            $refreshAt =
                $expiresAt.AddMinutes(
                    -$RefreshBufferMinutes
                )

            if ((Get-Date) -ge $refreshAt) {
                return $true
            }
        }
        catch {
            return $true
        }

        return $false
    }


    function Invoke-CompanyCredentialRefresh {

        Write-Host ""
        Write-Host "========================================"
        Write-Host " Copilot OSS Authentication"
        Write-Host "========================================"
        Write-Host ""

        if (-not (Test-Path $CompanyRefreshScript)) {

            throw @"
    Company credential refresh script was not found:

    $CompanyRefreshScript
    "@
        }

        #
        # Dot-source the existing PowerShell script.
        #
        # This allows environment variables populated by the
        # refresh script to remain visible to this process.
        #
        . $CompanyRefreshScript

        $credential =
            Get-ProcessEnvironmentVariable `
                -Name $RefreshOutputEnvVar

        if ([string]::IsNullOrWhiteSpace($credential)) {

            throw @"
    Authentication completed but the refresh script
    did not populate:

    $RefreshOutputEnvVar

    Update the refresh script so that after Azure SSO
    success it sets:

    `$env:$RefreshOutputEnvVar = <generated credential>
    "@
        }

        #
        # Map the generated credential into the environment
        # variable expected by Copilot / Bedrock integration.
        #
        Set-ProcessEnvironmentVariable `
            -Name $CopilotCredentialEnvVar `
            -Value $credential


        #
        # Do not keep unnecessary duplicate copies.
        #
        if ($RefreshOutputEnvVar -ne $CopilotCredentialEnvVar) {

            [Environment]::SetEnvironmentVariable(
                $RefreshOutputEnvVar,
                $null,
                [EnvironmentVariableTarget]::Process
            )
        }


        $issuedAt = Get-Date

        #
        # Prefer actual expiration from the auth system
        # if the existing refresh script can expose it.
        #
        $expirationValue =
            Get-ProcessEnvironmentVariable `
                -Name "COMPANY_COPILOT_KEY_EXPIRES_AT"

        if (-not [string]::IsNullOrWhiteSpace($expirationValue)) {

            try {
                $expiresAt =
                    [DateTime]::Parse($expirationValue)
            }
            catch {
                $expiresAt =
                    $issuedAt.AddMinutes(
                        $CredentialLifetimeMinutes
                    )
            }
        }
        else {

            $expiresAt =
                $issuedAt.AddMinutes(
                    $CredentialLifetimeMinutes
                )
        }


        Save-AuthState `
            -IssuedAt $issuedAt `
            -ExpiresAt $expiresAt


        Write-Host ""
        Write-Host "Authentication successful."
        Write-Host "Credential expires approximately:"
        Write-Host "  $expiresAt"
        Write-Host ""
    }


    function Set-CopilotModel {

        Set-ProcessEnvironmentVariable `
            -Name $CopilotModelEnvVar `
            -Value $CopilotModel
    }


    function Show-CopilotStatus {

        $state = Get-AuthState

        Write-Host ""
        Write-Host "========================================"
        Write-Host " Copilot OSS Development"
        Write-Host "========================================"

        Write-Host "Repository : $((Get-Location).Path)"
        Write-Host "Model      : $CopilotModel"

        if ($Continue) {
            Write-Host "Session    : Continue previous"
        }
        else {
            Write-Host "Session    : New/current"
        }

        if ($null -ne $state) {
            Write-Host "Expires    : $($state.expiresAt)"
        }

        Write-Host "========================================"
        Write-Host ""
    }


    # ============================================================
    # MAIN
    # ============================================================

    $refreshRequired =
        Test-CredentialRefreshRequired


    if ($refreshRequired) {

        Invoke-CompanyCredentialRefresh
    }
    else {

        Write-Host ""
        Write-Host "Existing Copilot credential is still valid."
    }


    Set-CopilotModel

    Show-CopilotStatus


    if (-not (Get-Command copilot -ErrorAction SilentlyContinue)) {

        throw @"
    Copilot CLI was not found in PATH.
    "@
    }


    if ($Continue) {

        & copilot --continue
    }
    else {

        & copilot
    }


    $exitCode = $LASTEXITCODE

    exit $exitCode

TOKEN LIFETIME HANDLING
-----------------------

Do not wait for the exact 60-minute expiration boundary.

Recommended values:

    Token lifetime:     60 minutes
    Refresh buffer:      8 minutes
    Effective refresh:  ~52 minutes

Reason:

Starting a new agentic task with only a few minutes of credential life remaining creates avoidable mid-task failures.

Example:

    Token issued:  09:00
    Actual expiry: 10:00
    Refresh-after: 09:52

If a developer runs:

    ai

at 09:55, authenticate first.

If a developer runs:

    ai

at 09:20 and the current PowerShell process still holds the valid credential, launch Copilot directly.


IMPORTANT ENVIRONMENT-VARIABLE BEHAVIOR
---------------------------------------

A running Copilot CLI process inherits environment variables when it starts.

Updating an environment variable in another PowerShell process generally does not update the environment of an already-running Copilot process.

Therefore the recommended hourly lifecycle is:

    Copilot CLI session
          |
          +-- credential eventually expires
          |
          +-- exit CLI if required
          |
          +-- run aic
                  |
                  +-- authenticate
                  +-- new process-scoped environment
                  +-- copilot --continue
                  +-- previous task context restored

Do not design around injecting new credentials into an already-running process unless Copilot CLI or the company's integration explicitly supports that behavior.


TASK LIFECYCLE VS CREDENTIAL LIFECYCLE
--------------------------------------

These must remain independent.

Example three-hour engineering task:

    Engineering task
    -------------------------------------------------->

    Credential 1
    ----------------

                   Credential 2
                   ----------------

                                  Credential 3
                                  ----------------


The developer experience should be:

    Task ABC
       |
       +-- Credential 1
       |
       +-- Refresh
       |
       +-- Credential 2
       |
       +-- Refresh
       |
       +-- Credential 3


The developer should never have to reconstruct the task because the credential expired.

PERMISSION MODEL
----------------

One of the largest CLI adoption risks is excessive approval prompts.

Do not blindly enable unrestricted execution.

Instead, establish a company-approved safe command policy.

Examples that may be appropriate to auto-allow depending on company policy:

    Read files
    Search files
    Modify files inside the repository
    git status
    git diff
    git log
    pytest
    npm test
    mvn test
    gradle test
    local lint
    local format
    local compile/build

Examples that should normally remain restricted or explicitly approved:

    git push
    git reset --hard
    production deployment
    terraform apply
    destructive kubectl operations
    destructive database operations
    credential retrieval
    secret access
    commands outside the workspace

The objective is:

    Copilot
       |
       +-- read
       +-- edit
       +-- test
       +-- fix
       +-- test

without repeated prompts for low-risk development actions.

    aic


AUTH FAILURE / FORCE REFRESH

    air


SMALL QUESTION

    Copilot Chat or the currently-running CLI session


LARGE / TOKEN-HEAVY TASK

    Copilot CLI + company OSS model


SOURCE REVIEW

    Visual Studio Code diff


PROJECT CONTEXT

    Existing .github instructions, skills, and agents


CREDENTIALS

    Process-scoped only


TOKEN EXPIRATION

    Authenticate and resume with aic


Do not ask developers to learn a large CLI command catalog during initial rollout.


ADOPTION PRINCIPLES
-------------------

1. Do not make CLI adoption a process-adoption exercise.

2. Engineers remain in Visual Studio Code.

3. CLI is simply another pane inside the existing development environment.

4. The company OSS model should handle token-heavy work.

5. Do not require developers to manually select the model every time if the existing environment setup can provide the default.

6. Do not ask developers to manually paste project instructions.

7. Do not duplicate .github context.

8. Keep authentication as close to one command plus required SSO as possible.

9. Preserve engineering sessions across credential expiry.

10. Let the model perform longer analyze-implement-test-fix-review loops where doing so saves developer time.

11. Use available tokens productively rather than optimizing only for token reduction.

12. Keep human review of generated code.


SUCCESS METRICS
---------------

The rollout should target:

    Normal CLI launch:
        1 command

    Credential refresh:
        1 command + mandatory SSO

    Manual copying of generated credential:
        0

    Manual environment-variable setup:
        0

    Repeated manual model setup:
        0

    Re-pasting project instructions:
        0

    Re-explaining work after hourly token refresh:
        0

    Existing .github restructuring:
        0

    Persisted hourly credentials:
        0

    Developer return to work after successful SSO:
        Immediate or near-immediate

    CLI usage for large/token-heavy engineering work:
        Increasing

    Premium-model escalation:
        Used primarily when OSS models are insufficient


RECOMMENDED ROLLOUT ORDER
-------------------------

1. Fix the credential handoff.

2. Deploy ai / aic / air.

3. Verify session continuation.

4. Verify existing .github instructions, skills, and agents.

5. Pilot with a small engineering group.

6. Measure friction.

7. Optimize permissions.

8. Improve instructions where the model wastes time rediscovering repository mechanics.

9. Improve existing skills for repetitive engineering workflows.

10. Add convenience features such as VS Code task integration only after the core workflow is stable.


FINAL TARGET STATE
------------------

The final experience should be:

    Developer opens Visual Studio Code.

    Developer works normally.

    For a quick AI interaction:
        use Copilot Chat.

    For a large/token-intensive task:
        open integrated terminal.

        run:

            ai

    Authentication occurs only when necessary.

    Company OSS model is configured.

    Copilot CLI uses the same repository and existing .github
    instructions, skills, and agents.

    Copilot performs repository analysis, implementation,
    tests, fixes, and review.

    Developer reviews changes through Visual Studio Code.

    When the one-hour credential expires:

        run:

            aic

    Complete mandatory Azure SSO.

    The previous Copilot session resumes.

    Development continues without reconstructing task context.


This design intentionally adds the smallest possible layer around the existing approved authentication and Copilot CLI workflow while preserving the team's existing Visual Studio Code and .github-based development practices.
